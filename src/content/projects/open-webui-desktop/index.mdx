Open WebUI Desktop is a macOS app for [Open WebUI](https://github.com/open-webui/open-webui), the self-hosted chat interface for LLMs. It wraps your Open WebUI instance in a desktop window and adds the two ChatGPT desktop features I missed most: a floating chat bar you summon with a hotkey, and a companion chat that keeps the conversation on screen while you work.

I built it with Tauri and Svelte in December 2024 and released v0.1.0 for macOS in January 2025. Download it from the [releases page](https://github.com/reecelikesramen/open-webui-desktop/releases/tag/v0.1.0) or browse the source on [GitHub](https://github.com/reecelikesramen/open-webui-desktop).

# The Problem

Open WebUI had no desktop app, and people in the community kept asking for one. I wanted to use it. I agree with its creator's views on owning your data and running your own models. But ChatGPT's floating chat bar and companion chat kept pulling me back. As a developer I use both constantly, and I couldn't switch without them.

# The Plan

The two options for turning a web app into a desktop app were Electron and Tauri. I picked Tauri because I already knew Rust, and because Tauri 2 can also target mobile. Open WebUI's front end is Svelte, so I could fork it, change as little as possible to run it inside Tauri, and build the chat bar and companion chat on top. Keeping the fork close to upstream meant I could pull in new Open WebUI releases instead of reimplementing them.

# How It Works

## Connecting to Open WebUI

Open WebUI is a Python API that serves a Svelte front end as static files. The desktop app bundles the front end and assumes you already run an Open WebUI server, locally or hosted somewhere. On first launch it asks for that server's URL, and that's the only setup. Connecting only took one real change: turning the API base URL from a constant into a setting.

## Sharing state between windows

Svelte shares state through writable stores, and it can persist state in local or session storage. In Tauri, each window is its own web view, so none of those are shared between the main window, the chat bar, and the companion chat.

I wrote a cross-window store that looks like a normal Svelte writable. Underneath, it keeps each value in [tauri-plugin-store](https://v2.tauri.app/plugin/store/), which lives in the app's Rust process. Every window subscribes to changes for its keys, so when one window sets a value, the others update reactively. Values can also persist to a file, which made saving settings between launches almost free. Components use it like any other store, so the forked code stayed idiomatic Svelte.

**_cross-window-writable.ts_** (trimmed; logging and some edge cases removed)

```ts
export function crossWindowWritable<T>(name: string, initialValue?: T, persist = false): Writable<T> {
  const wrappedStore = writable<T>(initialValue)
  let currentValue = get(wrappedStore)

  // Writables must be returned synchronously, so connect to the backing store in the background
  const storePromise: Promise<Store | null> = (async () => {
    const store = (await getStore(APP_STORE_FILE)) || (await load(APP_STORE_FILE, { autoSave: false }))

    // Start from the stored value if there is one, otherwise seed the store
    const stored = await store.get(name)
    if (stored !== undefined) {
      currentValue = stored as T
      wrappedStore.set(currentValue)
    } else if (initialValue !== undefined) {
      await store.set(name, initialValue)
      await store.save()
    }

    // Pick up changes made by other windows
    const unlisten = await store.onKeyChange(name, (newValue: T | undefined) => {
      if (newValue === undefined || equal(newValue, currentValue)) return
      currentValue = newValue
      wrappedStore.set(newValue)
    })
    getCurrentWindow().once("tauri://close-requested", unlisten)

    return store
  })()

  const set = (value: T) => {
    if (value === undefined || equal(currentValue, value)) return
    currentValue = value
    wrappedStore.set(value)
    storePromise.then(async (store) => {
      await store?.set(name, value)
      await store?.save()
    })
  }

  return { set, subscribe: wrappedStore.subscribe, update: (updater) => set(updater(currentValue)) }
}
```

## The chat bar and companion chat

Open WebUI's chat page is one [2,000-line Svelte component](https://github.com/open-webui/open-webui/blob/main/src/lib/components/chat/Chat.svelte), and the pieces I needed were tightly coupled to the rest of it. I could either break it into modules or copy it and strip out what the chat bar didn't need. Breaking up someone else's code only helps if upstream takes the change, and I didn't expect that soon. So I kept a trimmed copy, which is easier to keep in sync with upstream than my own refactor of code I didn't write.

With the components in place and state shared with the main window, the rest was:

- A global hotkey to summon the chat bar
- Show and hide behavior that matches ChatGPT's
- Styling that matches Open WebUI's themes

The companion chat stays on screen for 10 minutes after the last message and remembers where you put it, and it can open the conversation in the main window.

## Settings

A new pane in Open WebUI's settings covers the desktop features:

- The hotkey for the chat bar
- Where the chat bar appears on screen
- How long the companion chat stays open
- Launching at startup
- The Open WebUI server URL

# Where It Stands

v0.1.0 was downloaded more than 50 times in its first 10 days, and Open WebUI's creator and a few contributors reached out about it. I took part in the discussions about an official desktop app. Open WebUI chose Electron over Tauri because of concerns about Tauri's long-term support and stability, and parts of this project, including the floating chat bar and the logic for connecting to a hosted or on-prem server, carried into the official [Open WebUI Desktop](https://github.com/open-webui/desktop) app.

This fork still gets dependency updates, and a community contributor fixed its Linux build in August 2025.
